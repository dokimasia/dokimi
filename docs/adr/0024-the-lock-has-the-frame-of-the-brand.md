# ADR-0024: The lock has the frame of the brand

## Status

Accepted

## Context

The lock of a plan is a data file of eidos. A data file had no frame, so a sink recognised the lock
only by the digest that the manifest in `.dokimi/` records for its path. dokimi tells a repository
to ignore `.dokimi/`, so a fresh clone and a CI job have no manifest. A run there classified the
lock as foreign and failed with `EID-0056` as soon as the lock gained or lost a line, such as for a
new suite.

With `plugin.Output.Comment`, a data family of eidos states the comment syntax of its file. The run
stamps the file with the frame of the brand in that syntax. A sink then classifies the file through
its frame, as it classifies a generated source file, and it does not read the manifest for that.

## Decision

We will declare the comment syntax `#` on the family of the lock, because the frame is the record
that a fresh clone has of the files that dokimi wrote.

- The run stamps the lock with the frame of dokimi: the marker
  `# Code generated by dokimi. DO NOT EDIT.`, the line `# dokimi:plugin suite`, a blank line, the
  lines of the lock, a blank line and the trailer `# dokimi:provenance sha256:<digest>`.
- A run in a clone without `.dokimi/` writes over the lock that dokimi wrote, and refuses a file
  of a person at its path with `EID-0056`.
- The run refuses an edit of the lock by hand as drift, unless the run has `--overwrite-drift`.
- `run --check` compares the lines between the frame and the trailer, and `LostCheck` reports a
  lost line at its line in the committed lock.
- The reader of the corpus skips the lines of the frame, as it skips the comment lines and the
  empty lines of the lock.

## Alternatives Considered

### `.dokimi/` in the repository

The manifest records the digest of every generated file, so every change of a generated file
changes a document of `.dokimi/`. The sealed state beside the manifest changes with the reads of
each run.

### The header line `# dokimi lock 1` as the proof

A header does not contain a digest of the lines. The run would overwrite a file that a person
writes with the header. The check of drift compares a body with its digest, so the run would also
overwrite an edit of the lock.

## Consequences

**Positive:**

- A change that adds or removes a suite regenerates the lock in a fresh clone and in CI.
- An edit of the lock by hand fails the run as drift.

**Negative:**

- The lock has five lines more than its records, and its trailer changes with every change of its
  records.
- A tool that reads the lock skips the lines of the frame.
- A committed lock without the frame remains foreign in a clone without `.dokimi/` until a run
  with `.dokimi/` or with `--adopt` writes the framed lock and a commit contains it.
